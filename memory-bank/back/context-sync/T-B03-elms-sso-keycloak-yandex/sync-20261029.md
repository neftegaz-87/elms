## Rationale

- Эпик T-B03 (`elms-sso-keycloak-yandex`) полностью реализовал и валидировал контур единой точки входа (SSO) для платформы ELMS:
  1. **Keycloak Realm & Client:** В `docker/keycloak/realm-elms.json` сконфигурирован realm `elms`, confidential клиент `elms-frappe` с каноническим redirect URI `/api/method/frappe.integrations.oauth2_logins.login_via_keycloak` и brokered OIDC IdP `yandex` с точкой терминации `/realms/elms/broker/yandex/endpoint`.
  2. **Секреты и конфигурация:** Frappe `site_config` содержит исключительно `keycloak_login` (`client_id`, `client_secret`). Учетные данные Yandex передаются строго в контейнер Keycloak. Открытые секреты в git tracking отсутствуют (проверено статическим тестом).
  3. **Frappe Social Login Key:** В Frappe создается ровно один Social Login Key (`Keycloak`). Прямой Social Login Key Yandex или параллельные OAuth-модули в Frappe полностью исключены (SC-001, FR-010). Флаг активности контролируется наличием учетных данных (conf-gating).
  4. **JIT-провижининг и роли:** Пользователи создаются strictly Just-in-Time при первом входе через брокер Keycloak, связываясь по `sub` и подтверждённому email. Хук `User.after_insert` (`maybe_assign_sso_roles`) гарантированно присваивает роли `Desk User` и `ELMS LMS User`. Если роль отсутствует в базе данных, операция выбрасывает `frappe.throw` (fail-closed, запрещено создание учетной записи без прав, AC--3, TM-005).
  5. **Регламент сбоев и fallback:** Сбой внешнего IdP Yandex блокирует вход без создания фиктивных сессий (fail-closed). Для утверждённых пользователей документирован и верифицирован вход по локальному паролю Keycloak (`fallback.user@elms.local`), а для аварийного восстановления — локальный вход системного администратора в Desk UI (Break-Glass Level 2).
  6. **Верификация:** Все 44 теста в `elms/elms/tests/` (13 RBAC, 31 SSO) проходят успешно за 0.07s в `bin/pytest`. Все приемочные критерии (AC-1..AC-8, AC--1..AC--4) подтверждены артефактом QA (`qa-20261029-sso.yaml`).
