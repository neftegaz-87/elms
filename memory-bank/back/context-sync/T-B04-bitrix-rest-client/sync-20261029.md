## Rationale

- Эпик T-B04 (`bitrix-rest-client`) полностью реализовал и валидировал клиентский транспорт и CLI-инструментарий для взаимодействия с Bitrix24 REST API:
  1. **Изолированный транспорт и валидация границ:** В `scripts/bitrix/rest_client.py` реализованы модели `WebhookEndpoint`, `CallArgs`, `RestEnvelope`, функция `post_json` и типизированное исключение `BitrixRestError`. Взаимодействие построено на базе стандартной библиотеки `urllib.request` с Pydantic-валидацией параметров.
  2. **Строгая изоляция учетных данных:** Конфигурация входящего вебхука читается строго из переменной окружения `BITRIX_REST_WEBHOOK_URL` формата `https://<domain>/rest/<user_id>/<webhook_code>/`. Тихий fallback на переменную доски `BITRIX_WEBHOOK_URL` исключён: при отсутствии или пустом значении целевой переменной скрипты немедленно завершаются с кодом 2 без выполнения сетевых вызовов (AC-3, BN-001, BN-002, TM-003).
  3. **CLI-инструменты и семантика кодов выхода:** Разработаны CLI `scripts/bitrix/call.py` (вызов любого REST-метода с передачей JSON-параметров через `--params`) и `scripts/bitrix/scope.py` (проверка прав и скоупов вебхука, флаг `--full`). Соблюдён детерминированный контракт: `0` — успех (JSON в stdout), `1` — ошибка Bitrix API (`error`, `error_description`) или сетевой сбой HTTP (stderr, stdout пуст), `2` — ошибка валидации аргументов, URL или окружения (stderr, stdout пуст, HTTP-запрос не отправляется).
  4. **Защитные лимиты и маскирование секретов:** Встроен локальный batch guard, отклоняющий запросы метода `batch` с более чем 50 командами или вложенными вызовами `batch` с кодом 2 до отправки в сеть (AC-6, BN-005, TM-006). Обеспечено надёжное маскирование секретной части токена вебхука во всех сообщениях об ошибках, строковых представлениях моделей и трассировках исключений (TM-007).
  5. **Эксплуатационная документация:** Создана пошаговая русскоязычная инструкция `docs/bitrix-incoming-webhook.md` по выпуску вебхука на стороне Bitrix24, настройке прав доступа и безопасной конфигурации окружения. В `.env.example` добавлен блок с переменной `BITRIX_REST_WEBHOOK_URL`.
  6. **Верификация:** Разработан тестовый набор из 37 автоматизированных тестов (`tests/bitrix/test_rest_client.py`), использующий детерминированный mock `urllib.request.OpenerDirector` без выхода в реальную сеть. Все 37 тестов проходят в `unittest` (0.007s) и `pytest` (0.10s). Общий набор тестов репозитория вырос до 81 теста. Все приемочные критерии (AC-1..AC-6, AC--1..AC--5, BN-001..BN-007) подтверждены артефактом QA (`qa-20261029-bitrix-rest.yaml`).
