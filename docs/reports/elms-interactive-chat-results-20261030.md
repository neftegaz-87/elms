# ELMS — результаты интерактивной работы

Дата: 30 октября 2026 года  
Статус: выполнено и проверено в работающем окружении

## Что было сделано

1. Экран входа переименован в «Вход на сайт ELMS СДО».
2. В форму стандартного входа Frappe подключена серверная аутентификация через Keycloak. Отдельная кнопка «Войти через Keycloak» не используется.
3. Восстановлен визуальный стиль login-поверхности по образцу `neftegaz-ai-layer`: цвета, поля и кнопки высотой 44 px, радиус 3 px, состояния focus/hover/active/disabled и адаптация под reduced motion.
4. Исправлена потеря CSS после перезапуска контейнеров: сборка и доставка Frappe-ассетов проверяются в работающем runtime.
5. Desk приведён к LMS-first навигации: LMS открывается первым, а служебные ERP/CRM/Website-инструменты исключены из пользовательской навигации. Роли и доступы оставлены источником истины приложения ELMS/LMS.
6. Настроен Keycloak realm `elms`, клиент `elms-frappe`, внутренний URL для backend и публичный URL для браузера.
7. Добавлены локальные тестовые аккаунты Keycloak с ролями и группами:
   - `elms.test.one@elms.local` — `employee`, `/Employees`;
   - `elms.test.two@elms.local` — `employee`, `/Employees`;
   - `elms.test.admin@elms.local` — `admin`, `/Administrators`.
8. Пароли тестовых аккаунтов вынесены в игнорируемый `docker/.env.dev`; в отслеживаемых файлах секретов нет.
9. Проверен JIT-сценарий: после входа Keycloak-пользователь может быть создан в LMS с ролями `Desk User` и `ELMS LMS User`. На момент передачи результата соответствующие тестовые пользователи удалены из LMS, чтобы ручная проверка начиналась с чистого состояния.

## Почему работа считается успешной

- password grant Keycloak успешно прошёл для всех трёх аккаунтов;
- headless Chromium browser QA подтвердил вход через форму и переход в `/app/lms`;
- CSS login-страницы после перезапуска отдаётся с HTTP 200;
- `bench`-тесты и live smoke завершились успешно;
- проверено, что тестовые аккаунты существуют в Keycloak, но не существуют в LMS до следующего входа.
